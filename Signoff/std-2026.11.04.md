# Sign-off: std-2026.11.04 (wanda_network_v1 1.4.0, pipe_function 1.4.0)

- Approved by: James (WRc), 04/11/2026, in session (open question STANDARD-1.4.0 APPROVED 04/11): a WRZ label on every
  DMA; a WRZ outline layer; three pipe tiers (transmission, trunk, distribution); filed client data stays valid. No
  further signature is needed for the items above.
- Rulings it rests on (Hub\02_Open_Questions.md): CAT-Q16 (30/10: WRZ is a standard UK area definition; wrz_ref on DMA areas
  + a WRZ polygon layer), WRZ-SHAPE (04/11: a DMA is in one WRZ; zones are whole DMAs), PIPE-TIERS (04/11: transmission =
  grid-type mains; trunk = mains that can still be in a DMA, with no or limited customers; distribution = normal DMA mains;
  the tier matters mainly for client reporting; a transmission section gets no DMA assignment just because of a pipe's
  size), WI-FULL-REBUILD (04/11: the WRZ goes into the standard as a new version within the one full WI rebuild).
- Scope: additive. A 1.3.0 set still reads (wrz_ref blank, no WRZ layer; a filed `trunk` stays `trunk`). 1.3.0 frozen in
  `_frozen/network_1.3.0`; pipe_function 1.3.0 frozen in `_frozen/pipe_function_1.3.0` (as 1.2.1 and pipe_function 1.2.0
  were frozen for 1.3.0).
- Meaning (James 04/11): the models bring the traces regardless of assignment to a polygon or WRZ; a WRZ is a term a company
  uses for a section of its network, normally relating to a source of water. Zones are labels and never drive hydraulics.
- Consumers that must accept 1.4.0 before any 1.4.0 set is filed: the new `water_resource_zones` layer and
  `dma_areas.wrz_ref` (an unread layer is ignored), and the new pipe code `transmission`. Wherever `trunk` counts as a main
  (wanda_common wanda_gis_rules.MAIN_FUNCTIONS, wanda_import derive.py and health.py, PLDR pldr_wanda_codes.PLDR_MAIN_FUNCTIONS
  and their pin tests), `transmission` must count too, or transmission mains drop out of the mains logic.
- Branch hold: this branch reaches main (the WANDA_SCHEMA_DIR default) only after wanda_import 1.4.0 merges.

## Build decisions made while building (inside the approved three tiers; not separately approved)

- The tiers are read from the existing `pipe_function` code list by adding one code, not by a new field or a size rule:
  `trunk` already existed, the generator already writes its transmission pipes as the trunk-coded (cwTransmissionPipe), and
  a code list is the standard's one place for pipe classes. A diameter rule is excluded by PIPE-TIERS.
- `transmission` has serves_customers null (module decides) and potable_network true, the same as `trunk`, so a filed pipe
  keeps today's behaviour when a client moves it from trunk to transmission.
- Synonym "grid" / "grid main" recode to `transmission`. A client's own class is recoded in its mapping (PIPE-TIERS: client
  classification is not fixed). For STW, how the grid is assigned in its GIS still has to be checked and followed.
- The WRZ and WQZ wording follows the regulator definitions as briefed; they were not re-checked against the regulators' texts.
